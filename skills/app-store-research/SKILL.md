# App Store 竞品调研

不靠印象和搜索摘要，**直接打官方接口拿真实数据**。整套流程零依赖（python3 标准库 + curl），单条命令出结果。

## 核心方法：四步，顺序不能倒

### 1. 先全量扫描，再谈其他

```bash
python3 scripts/probe.py search "地球online"
# ⚠️ --country 是全局参数，必须放在子命令**之前**
python3 scripts/probe.py --country us search "habit tracker" --limit 20
```

结果自动按**评数**降序。**这一步是防漏网，不是可选项。**

> ⚠️ **真实教训**：做「地球Online」调研时，我凭关键词人肉搜只找到 2 个产品，后来用这个接口全量扫才发现**漏掉了体量是另一个 7 倍、上架最早、迭代到 4.1.0 的真正头部**。关键词搜索会被算法影响，接口不会。

**判断赛道的三个信号**：

| 信号 | 含义 |
|---|---|
| 头部评分 4.5+ 且评数 1000+ | 概念已被市场验证，不是空白赛道 |
| 有多个同名产品 | 概念有热度，但也意味着**名字已被占用、搜索会被分流** |
| 上架时间都很近（几个月内） | 风口刚起，新入者还有机会 |

> 💡 **找「参照物」要搜机制词，不要只搜品类词。**
>
> 品类词（`habit tracker`）只会召回路子最像的产品，**头部会把小众精品淹掉**。而搜**机制词**能召回"某个机制做得特别好"的产品，哪怕品类不同——这才是可抄的对象。
>
> 真实案例：要找「分享卡做得好的产品」，搜 `habit tracker` 时 **Petal: 75 Soft Challenge**（把 75 天做成"一朵花"，Day 25/50/75 自动生成竖版 1080×1920 里程碑卡、一键分享）没进前 8；搜 `habit tracker streak widget` 才浮出来。
>
> 常用机制词：`streak widget` · `share card` · `pet widget` · `with friends` · `accountability` · `challenge`

### 2. 拉元数据，判断成熟度

```bash
python3 scripts/probe.py meta 6755080871 6789109191
```

重点看四个字段：

- **版本号**——迭代到 3.x/4.x 说明产品线长期投入（这是最真实的成熟度信号）
- **评数 / 上架时间**——算日增评分，判断它还在涨还是已经凉
- **`currentVersionReleaseDate`**——最近更新在几天内说明团队还活跃
- **分类 `genres`**——决定你和它的竞争强度，注意很多同类产品把分类放在「生活/效率」而非「健康健美」

### 3. 拉内购清单，看它怎么赚钱

```bash
python3 scripts/probe.py price 6755080871
```

拿到的是「项目名 + 价格」配对，这是**定价决策最直接的依据**。

**关键判断：档位数量和评分的相关性**

> 实测：一个 3067 评的产品挂了 **8 个内购**（年付三个价 ¥168/198/328、月付两个价 ¥68/128），评分 4.56；
> 另一个 439 评的产品只有 **3 档**（¥18 月 / ¥118 年 / ¥298 终身），评分 4.87。
> **定价越复杂，用户越难决策，评分往往越低。别盲目学档位多的那个。**

还要看**年付相对月付的折扣**，反推它在主推哪一档。

### 4. 挖评论：差评里有机会，好评里有用户画像

```bash
python3 scripts/probe.py reviews 6755080871 --stars 3   # 只看 3 星及以下
```

**先判断评论有没有得挖**：4.9 分基本没有差评，挖不动；4.5 分左右必有货。

拿到评价后的读法：

- **差评指向的多是"可免费避开的坑"**——实测某产品的 3 星差评直指隐私政策写得笼统（"没写明照片会用来干什么"），而这正是 2026 年 App Store 第一大拒审原因。这类问题**你只要不犯就赢了一程**
- **好评的共性词才是它真正的卖点**——用户说的"有成就感""趣味性"才是他付费的理由，不是功能列表
- 好评样本量太小时（比如只剩 5 星刷屏），**转向"它没做什么"**——成熟度高的产品短板往往在"没做的部分"，不在"做错的部分"

**评论的第二个用途：提取目标用户画像**（实测很准）

用户会在评论里**自述身份、场景、痛点**——这是最可靠的一手用户研究，比二手行业报告准得多（实测行业报告讲的"健康管理 App 用户以 31-40 岁为主"根本套不到自我提升类产品上）。

做法：

1. 用 `search` 找**同品类头部产品**——**按评数排序，不要按评分**（评分高的可能只有几十条评价）
2. 每个抓十来条评论，**逐条读原文**，摘出带身份线索的句子
3. **看反复出现的自我描述**——那才是真实画像

实测案例（习惯类）：6 个独立来源的用户原话指向同一群人——
「希望两年之后能在**理想的高中**再次打开这个软件」｜「有些项目的时间（**课程时间**）…」｜「**学生上班族**都非常适合」｜「对于我这种**需要利用手机学习的人**」

→ 最终结论不是"18-25 岁"，而是 **「有目标、但靠自己坚持不下来的人」**（评论高频自述："我这种懒惰用户""自制力差""静不下心""需要监督"）。

**两条经验**：

- **看痛点，不看年龄**。年龄是标签，痛点是需求——文案和功能都该对着痛点写。
- **意外收获常在这里**。实测拿到一条原话「**最后千万不要加社交功能，我只想安安静静自己打卡，不想聊天，不想交友，不想互相督促**」——**直接推翻了一个功能规划**。这种证据比"我们觉得社区有价值"硬得多。

## 三个已踩过的坑

| 坑 | 现状 | 正解 |
|---|---|---|
| **评论 RSS 已下线** | `itunes.apple.com/{cn\|us}/rss/customerreviews/...` 全部返回空 entry，但网上大量教程仍指向它 | 改用 `?see-all=reviews` 页面（SSR，可直接 curl） |
| **抓定价混入推荐位价格** | 直接正则抓 `¥` 会把 Apple 推荐位上**别的 App** 的价格一起抓进来（实测混进过 ¥228/¥368/¥688） | 只匹配 JSON 里的 `["名称","价格"]` 配对；退化方案是**先剥 HTML 标签**再去重 |
| **评论翻页参数无效** | `page=N`、`sortOrder=mostRecent` 都不起作用 | 一次只拿第一页约 10 条。要更多评论得上浏览器（ego-browser） |

其他注意：

- **WebFetch 抓 `apps.apple.com` 拿不到内购和评论**（动态渲染），只能拿基础信息块，别浪费调用
- 评论页 DOM 会改版，**旧的 `we-star-rating-stars-N` class 已不存在**，现在星级看 `aria-label="N 星"`
- 本机 HTTP_PROXY 会干扰请求，脚本内已禁用代理直连

## 从数据到决策

拿到数据后，按这四条转成可执行的结论：

1. **定价**——不抄单个数字，抄**结构**。看头部产品的档位梯度（年付通常是月付的 5–6 折、终身档约为年费的 2–2.5 倍），再按自己市场的价格带落位
2. **功能取舍分三堆**：直接抄（多产品共有 + 被好评印证）／ 改着抄（形态相似但产品逻辑不同）／ **不抄**（与自己的核心机制冲突——比如你的产品靠内在动机驱动，就别加经验值和金币商店，外部奖惩会挤出内在动机）
3. **找"都没做"的坑位**——比找"做得不好的"更有价值。多个竞品的共同空白，往往就是你的位置
4. **合规避坑**——差评里出现的隐私、退费、订阅陷阱，全是你上架前免费能躲开的雷
5. **⭐ 竞品在做 ≠ 你能做——先查平台规则**。见下

### 5 展开：平台规则优先于竞品做法

**"别人这么做"不构成"你能这么做"的理由。** 很多跑得通的玩法踩平台红线，尤其是**中国区的分享/裂变**。

必查两份文档：

- 微信《**外部链接内容管理规范**》（管链接）
- 微信《**小程序平台运营规范**》5.1「**滥用分享行为**」（管分享）

**明确违规的行为**（实测整理）：

| 违规 | 条款 |
|---|---|
| 强制分享——"分享后才能解锁 / 继续下一步" | 5.1.1 |
| **暗示分享——红点提醒分享、分享按钮动态变化** | 5.1.2 |
| 利益诱导——助力 / 砍价 / 集卡 / 集赞 / 分享得抽奖机会 | 5.1.3 / 外链规范 2.1.2 |
| **组队分享人数超过 5 人** | 5.1.8 |
| **分享量过大且转化率过低**（判为过度营销） | 5.1.9 |

**处罚是递进的**：限制链接在微信内打开 → 限制域名/IP → **限制分享接口能力** → 限制朋友圈二维码识别 → 下架封号。**"限制分享接口"等于砍掉整个裂变渠道。**

**没有"自己人"**：2026-02 微信把**腾讯自家的元宝红包**链接封了（"做任务领红包"诱导高频分享）。

**微信自己给出的合规路径**（原文）：**内容驱动分享**（用户因内容有价值自愿分享）✅ 安全 ／ 群内福利活动 ✅ ／ 合理助力 ⚠️需谨慎。
**唯一判断标准**：分享动机是「**自己想要**」还是「**被逼 / 被诱**」。

**两条可迁移的经验**：

- **优先"分享图片"而不是"分享链接"**——图片不走微信的链接审核体系；链接一旦被限，整条链路失效
- 当一个机制同时被「**与己方原则冲突**」和「**平台规则禁止**」两条独立路径否掉时，**它的定论优先级最高**——说明没有任何回旋余地，不用再讨论
