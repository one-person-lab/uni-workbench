# 内容知识系统

知识库不是把资料分得更漂亮，而是让资料进入行动、反馈、复盘和下一次调用。

## 判断处境

1. 没有知识库：建立最小结构并跑一条真实内容；
2. 收藏很多但用不起来：从当前问题反向检索，不扩目录；
3. 已有知识库规则：先读取其 README、AGENTS、索引或 Schema，适配现有结构；
4. 已有稳定生产：建立内容版本、反馈和方法资产关系。

不要强迫迁移工具或目录。

## 轻量输出

只给当前需要的最小结构或写回动作，并带一个真实示例。没有知识库时可建议：

```text
content-workspace/
├── inbox/       # 暂存真实材料
├── questions/   # 受众原话与问题
├── items/       # 内容版本和发布记录
├── methods/     # 经多次验证的方法
└── reviews/     # 发布和阶段复盘
```

先选一条真实材料跑通，不先设计完美体系。

## 最小内容记录

```text
来源经历/材料
→ 面向谁、解决什么问题
→ 内容版本
→ 发布位置
→ 数据和用户原话
→ 方法发生的变化
→ 下一次实验
```

问题库记录谁在什么场景、原话、当前替代方法、频率和强度、用户证据、最小验证动作。素材优先使用自己做过/失败过/验证过的事，其次真实对话、项目过程和复盘，最后外部资料。外部资料必须连接真实问题或行动。

## 从信息到可运行知识

- 知识卡只保留关键概念、概念之间的连接和用户自己的思考；一条外部知识只有连接了真实问题、场景、行动和反馈，才进入长期方法层。大段摘抄和漂亮分类不能代替理解。

  来源：转述自姜胡说《价值心法》第 4 章《阅读与理解》。

- 方法卡必须回答：在什么场景、遇到什么问题、怎么解决，并记录证据、失败和不适用边界。没有重复证据时仍标记为候选方法。

  来源：综合转述自姜胡说《价值心法》第 4 章《阅读与理解》和第 6 章《阅读、理解与思考》；证据状态为本项目补充。

- 素材入库时保留出处、标签和一条自己的理解；定期清理无用条目，并为未来调用建立索引。公开库不得收录完整书稿、字幕或私密资料。

  来源：转述自姜胡说《价值心法》第 7 章《每天写点什么》。

- 把长期问题当研究课题：收集案例和证据，形成一个公开版本，回收反馈，再记录理解变化并重写。

  来源：综合转述自姜胡说《价值心法》第 8 章《回归本质》和第 11 章《做有价值的事》；不承诺商业结果。

- 大文章、系列、SOP 或产品先拆成能独立提供价值的小片段，小范围验证后再合并和扩展。私密和付费材料不得为验证而公开。

  来源：转述自姜胡说《价值心法》第 16 章《阳谋！》；公开反馈不是唯一价值标准。

## 可直接写回的五类模板

用户要求“沉淀、写回、建立模板或 SOP”时，根据当前任务只选择最需要的一种模板，填入已有事实后交付。不要一次创建五张空卡。

“已经填好”不等于可以补齐缺失事实。每个字段只能使用用户明确提供的动作、步骤、结果和证据；缺失时写 `未知`、`待确认` 或“下一次验证”，不能把建议步骤倒写成用户已经做过的流程，也不能把模板默认结构说成“基于你已做过的真实动作”。

目标人群和材料类型不自动证明问题。用户说“面向想搭 AI 内容工作流的普通创作者”“把公开视频整理成 Skill”，不能据此填成“素材零散、检索难、用不起来”；若用户没有给出真正要解决的问题、适用场景或不适用边界，对应字段直接写 `待确认`。方法卡标题只描述已确认动作，不暗示“可复用、已验证、能提效”等结果。

评论里有人问步骤、另一些领取者没有产出时，不得写“说明卡点在步骤可复现性”或“很可能卡在步骤”。两组人是否重合、是否尝试过以及为什么没有产出都未知；只能分别记录事实，并把“补充真实步骤是否帮助产出”写成下一次待验证假设。

### 方法或 SOP 卡

```markdown
---
type: method
status: candidate | repeated | verified
---

# 方法名称

- 解决的具体问题：
- 适用人群与场景：
- 已使用次数与证据：
- 可复述步骤：
- 不适用边界：
- 失败或例外：
- 下一次验证：
```

单次成功只能标记为 `candidate`；出现跨内容、跨时间的重复有效证据后才能升级为 `repeated` 或 `verified`。

状态升级只依据用户提供的重复案例与实际结果，不自行规定“至少 1 人”“两三条”“若干次”等数字。拟议的新步骤、教程或实验统一放在“下一次验证”，不得混入“可复述步骤”冒充历史事实；历史步骤不足时保留 `待确认`。

## 资产升级

```text
问题卡 → 短口播 → 长解释/图文 → 案例与复盘 → 方法卡/SOP → Skill、模板、产品或服务
```

只有经多次使用和反馈的方法才进入长期方法层；单次金句或爆款不自动成为规律。

## 深度模式

用户明确要求完整系统时输出：现有资产审计；信息层级和状态；稳定内容 ID；原始材料只读规则；内容/发布/复盘/方法关系；索引与检索入口；迁移计划和风险。

## 写入边界

- 未经授权不创建、移动或重命名文件；
- 执行前读取并遵守当前环境的 `AGENTS.md`、Schema 和输出路由规则；
- NAS、云盘或外部知识库不可用时不回退到错误位置；
- 原始资料保持只读或版本化；
- 不把客户隐私、凭据和未经授权素材写入公开内容；
- 现有 Schema 优先于本文件的默认目录。

用户只要求方案时不要擅自写入。用户授权实施时，先确认路径和权限，再进行最小、可审查修改。

完成后最多建议一个下一步方向，不在本轮继续选题、写稿或复盘。
