# 图标选型（Neo-Brutalism 专用）

图标是 neo-brutalism 最容易翻车的地方——边框、投影、排版都对了，图标一软，整个界面就泄气。

## 三条硬标准

1. **线宽 ≥ 2.5px**（24px 网格下）。低于 2px 的线条放进 2px 黑边里会被完全压住
2. **几何刚性**：端点方或微圆（`stroke-linecap: square | butt` 优先于 `round`）、转角硬、造型方正。圆润饱满的图标与粗野主义语系冲突
3. **单色 currentColor**：图标本身不带颜色。色彩由容器（色块 / 徽章 / 选中态）提供

## 推荐图标集

### 首选：Phosphor Icons

理由：主流图标集中**唯一原生提供 6 档字重**（Thin / Light / Regular / Bold / Fill / Duotone）的。"粗"是一个原生档位，不需要靠调 `stroke-width` 去凑。Bold 档的视觉重量约等于 2.5–3px 线宽，与 2–3px 描边的组件天然同源。

| 场景 | 用法 |
|------|------|
| 导航、菜单 | `weight="bold"` |
| 主按钮、强调操作 | `weight="fill"` |
| 大号装饰性图标 | `weight="duotone"`（谨慎，仅用于空状态） |

- Vue 3：`@phosphor-icons/vue` → `<PhLightbulb weight="bold" />`
- React：`@phosphor-icons/react`
- 图标总数约 1500+，覆盖通用业务名词足够
- 网格：`viewBox="0 0 256 256"`（注意不是常规的 24）

### 备选：Material Symbols（Sharp 形态）

Google 的可变轴图标，覆盖最全（3000+），业务专有名词基本都能找到。

- 字重可调到 700，形态选 **Sharp**（不要 Rounded）
- 接入方式为字体 ligature：`<span class="material-symbols-sharp">lightbulb</span>`
- 代价：可变字体文件较大，且不如 SVG 组件灵活（无法按实例改色以外的属性）

### 备选：Lucide（需自行加固）

生态最大、维护最好、社区认知度最高。但**默认 2px 线宽偏细**。

加固方式（全局改一次即可）：

```css
svg.lucide {
  stroke-width: 2.75;
  stroke-linecap: square;
  stroke-linejoin: miter;
}
```

注意：这是"改出来的分量"，视觉上仍不如原生 Bold 档硬朗。适合项目已经用了 Lucide、不想换依赖的情况。

## 避免

| 图标集 | 为什么不行 |
|--------|-----------|
| Font Awesome | 线条老派、免费版图标覆盖少、授权提示烦 |
| Element Plus / Ant Design 内置图标 | 为"轻、细、克制"的表单界面设计，线宽普遍 1–1.5px，放进粗边里会被压住 |
| 彩色 3D / 拟物 / 扁平插画图标 | 与风格直接冲突 |
| Emoji | 见下 |

## 为什么不要用 emoji 当图标

1. **跨端渲染不一致**——macOS、Windows、Android、微信内置浏览器各有一套 emoji 字体，同一份代码在不同设备上长得不一样
2. **自带颜色与立体感**，且不可改。与"纯色块 + 黑边 + 平面"的语系是两个体系
3. **字重不可控**，无法与 700/900 的标题字重形成呼应
4. **不响应状态**——hover、选中、禁用时无法变色或改变形态
5. **造型逻辑不统一**——同为 emoji，💡 与 🎯 的透视、光感、笔画粗细毫无关系，摆在一起不成为一套

emoji 唯一的优势是零成本。一旦界面其他地方已经建立了秩序，它就会成为最弱的一环。

## 色彩补偿（关键）

**把彩色 emoji 换成单色图标，会丢失一个隐性功能：颜色区分。** 纯黑白黄的导航会变得更平。两种解法：

### 解法 1（推荐）：图标 + 色块容器

图标放进 4–6px 圆角的小方块里，方块背景从既有的语义色板循环取用。颜色由容器提供、形状由图标统一——既保留色彩识别，又统一造型语言。

```html
<span class="flex h-6 w-6 shrink-0 items-center justify-center rounded-[4px] border-2 border-black bg-neo-yellow">
  <PhLightbulb weight="bold" :size="14" />
</span>
```

注意：色块内的图标要缩小到 13–14px，否则会顶满方块失去呼吸感。

### 解法 2：单色 + 状态区分

图标全部保持墨色，靠选中态区分。更克制、更"高级"，但扫视识别速度慢一点。适合图标本身有强区分度的场景。

注意：这里的"选中态"指的是**抬起卡片**（白底 + 墨边 + 硬投影），**不是实心黑填充**。实心黑会把图标色块压住、让整列重心失衡，理由是导航列表专用，见 `components.md` 的「侧边导航 / 菜单列表」一节。

**选择标准**：导航项超过 6 个 → 用解法 1（需要颜色辅助定位）；导航项少于 4 个 → 解法 2 足够。

### 什么时候两种解法要混用（实战结论）

同一个产品里混用是常态，也是最优解。分界线只有一条：**图标是不是这一行的视觉锚点。**

| 场景 | 方案 | 理由 |
|------|------|------|
| 卡片式统计（一格里只有"标签 + 大数字"） | **色块容器** | 图标是卡片身份标识，卡片白底不冲突，色块还能恢复 emoji 原本的颜色区分功能 |
| 页面主标题（h1/h2 同级） | **单色行内** | 标题本身已是最重元素，色块会抢戏 |
| 区块标题（h3，后面跟一长串中文） | **单色行内** | 长文本前放色块会把标题切成两段，读起来累 |
| 按钮内 | **单色行内** | 按钮自己已有底色与描边，套色块是"边框套边框" |
| 徽章 / chip 内 | **单色行内或字符符号** | 空间太小，见下节 |
| 行内元数据（列表里的日期、作者） | **单色行内 14px** | 密度高，色块会让每行变重 |

判断口诀：**"这一行除了图标还有别的主角吗？"** 有 → 单色；没有（图标就是主角）→ 色块。

**统计卡容易漏掉的一格**：如果一行 4 格里有 3 格配了色块图标、第 4 格（比如"上次发布"）本来没图标，**要给第 4 格也补一个**。三缺一的不整齐比全不加更显眼。

## 什么时候该保留字符符号，不换图标

不是所有非拉丁字符都要换。**彩色 emoji 必须换，单色排版符号通常不换。**

| 符号 | 处理 | 理由 |
|------|------|------|
| `✅`（U+2705） | **换** | 彩色 emoji，跨端样式不一，无法继承字重 |
| `✓`（U+2713） | **保留** | 单色 dingbat，随字体渲染、跨端一致。在 12px 徽章里塞 11px 的 SVG 勾，线宽只剩 ~1.7px，反而不如 700 字重的字符勾清楚 |
| `‹` `›` `←` `→` | **看场景** | 纯几何导航按钮（`‹` `›`）保留；混在一堆图标按钮里的（"← 返回"）换成箭头图标，否则整个按钮区只有它没图标 |
| `＋` `·` `—` `…` | **保留** | 排版符号，不是图标 |

分界线的本质：**符号是否能随 `font-weight` 一起加粗、是否跨端一致。** 能 → 留着；不能（彩色 emoji、自带光影）→ 必须换。

注意：emoji 扫描正则里 `2600-27BF` 这段会同时命中 `✓`（U+2713）。**扫描结果要人工过一遍**，别把单色 dingbat 也当成待替换的 emoji。

## 尺寸规范

| 位置 | 图标尺寸 | 描边 |
|------|---------|------|
| 侧边导航、菜单项 | 16–18px | — |
| 页面主标题（text-2xl） | 22px | — |
| 区块标题（text-lg） | 18px | — |
| 按钮内 | 14–16px | — |
| 色块容器内 | 14px | 容器 24px，2px 描边 |
| 行内元数据 / 小标签 | 14px（下限） | — |
| 表格操作列 | 14px | — |
| 空状态 / 大号 | 40–64px | — |

**字号与图标尺寸的配对规律**：图标约为同行文字字号的 1.15–1.25 倍最自然。正文 14px → 图标 16px；标题 24px → 图标 22px（标题大了之后图标反而要收，否则比字还抢）；小标签 12px → 图标 14px。

**改标题时别忘把标题变成 flex**：原来写 `<h2>☀️ 今日工作台</h2>` 的，换成图标后要改成 `<h2 class="flex items-center gap-2">`，否则图标是 inline 元素，会和文字基线错位。用 flex 后 `gap` 负责间距，模板里图标标签与文字之间的换行缩进会被 Vue 的 whitespace condense 吃掉，不会多出一段空格。

**对齐**：图标与文字基线对齐，不要用 `vertical-align: middle` 凑。用 flex `align-items: center` 并给图标 `flex: none`，防止 flex 收缩导致变形。

## 迁移成本（实测数据）

- 23 个 Phosphor 图标组件 ≈ **+61 kB** 未压缩产物。原因：每个 `.vue` 组件内联了 6 档字重的全部路径数据，即使只用 `weight="bold"`，摇树也只摇到"组件"粒度，摇不掉其余 5 档。
- 这是可接受的（gzip 后增量约为 1/3），但**如果一次性要用 100+ 个图标**，改用 Iconify 的按需 SVG（`@iconify/vue` 或 `api.iconify.design/ph/<name>-bold.svg`）能省掉重复的字重数据。
- 参考规模：一个中等后台的 6 个视图，47 处 emoji → 47 个图标实例，涉及 19 个不重复图标。

## 迁移检查清单

- [ ] 全局搜索 emoji（Unicode 范围 `1F000-1FAFF`、`2600-27BF`、`2190-21FF`、`2B00-2BFF`）
- [ ] **人工过一遍扫描结果**，剔除 `✓`（U+2713）这类单色 dingbat
- [ ] 每个 emoji 找到语义对应的矢量图标（先验证组件名真实存在，别凭印象写）
- [ ] 统一字重档位（不用 `stroke-width` 凑）
- [ ] 确认颜色来自 `currentColor`，不硬编码
- [ ] 每个图标加 `shrink-0` / `flex: none`，防止在 flex 行里被挤压变形
- [ ] 带图标的标题 / 标签行已改成 `flex items-center gap-2`
- [ ] 色块容器的色板语义不冲突（尤其避开项目里表示"失败 / 危险"的颜色）
- [ ] 一行里如果有 N 格同类卡片，N 格全部配上图标，不留缺口
- [ ] 选中态、禁用态都有对应的图标处理
- [ ] 构建后确认 `vue-tsc` 零报错，并核对 bundle 增量符合预期
