# 产品适配、强度分级与交付验收

## 一、先回答一个问题：这个产品该不该用

Neo-brutalism 是**"喊出来"**的设计。判断一个产品该不该用，就看它是否需要"喊"。

### 适合（信号）

- 需要在一堆同类产品里被一眼记住
- 用户是年轻人或创意从业者
- 产品价值主张是"马上行动"而非"慢慢体会"
- 内容本身就有强承诺属性：投入了钱、时间、名誉
- 已经有明确的游戏化机制（积分、等级、连续打卡、成就）

### 不适合（信号）

- 用户处于焦虑、脆弱或需要被安抚的状态（医疗、心理咨询、借贷）
- 产品需要传递"权威、稳妥、不出错"（政务、银行、保险）
- 主要用户是老年人或低数字素养人群
- 品牌已有长期建立的柔和调性，换风格会割裂认知
- 界面信息密度本身就极高（复杂后台的专业报表），再加视觉重量会压垮可读性

### 灰色地带 → 用强度分级解决

大多数产品和"完全不适用"之间隔着很远。**不要用二元判断，用强度分级。**

## 二、强度分级实操

### L3 全量换皮

**执行**：全站 token 替换，所有组件按配方重做。

**风险**：原本靠留白和克制建立的高级感会消失；长列表、密集表单的可读性下降；如果产品调性偏柔和，会产生"视觉人格分裂"。

**上线前必须做**：找 3 个真实页面（首页、一个长列表、一个表单）做对照，确认可读性没有明显下降。

### L2 局部（默认推荐）

**识别"硬承诺元素"的方法**：问自己"这个元素出现时，用户正在做一件需要负责的事吗？"

典型清单：
- 主 CTA（"立即开始"、"确认支付"、"提交承诺"）
- 金额展示与支付流程
- 打卡 / 签到 / 连续记录
- 成就徽章、等级标识
- 警示条、失败态、风险提示
- 空状态（因为空状态需要引导行动）

**不动的部分**：导航、列表、设置项、个人资料、帮助内容、任何纯浏览类页面。

**关键纪律**：L2 下，风格元素要么**自成体系**（比如整个底部操作栏都是新的视觉语言），要么**加上明确语义**（这个按钮重，是因为它是主操作）。最忌讳的是在柔和界面里突兀地放一个硬边按钮——那不叫风格，叫串味。

执行技巧：给 L2 元素一整套一致的视觉语言（同描边宽度、同投影偏移、同等宽字体规则），让它读起来像一个"重量级图层"。用户会自然理解：长得重的 = 重要的 = 需要认真对待的。

### L1 点缀

只改一个元素。通常选主 CTA 或一组徽章。

效果是"记忆锚点"：用户记不住整个界面，但会记住那个按下去的按钮。成本最低，风险最小。

## 三、移动端减配规则

桌面端的参数直接搬到手机上会变成噪音。原因：屏幕小、DPR 高（3px 描边在 3x 屏上视觉等效 1px 却占 3 个物理像素）、手指点击需要更大靶区、长列表需要更低的视觉密度。

**等比降级表**：

| 参数 | 桌面 | 移动端 |
|------|------|--------|
| 描边宽度 | 3px | **2px** |
| 主投影 | `4px 4px 0` | **`2px 2px 0`** |
| 大投影（弹窗） | `8px 8px 0` | **`4px 4px 0`** |
| 小投影（按钮） | `2px 2px 0` | **`1px 1px 0`** 或直接用 `2px 2px 0` |
| 圆角 | 0 | 0–2px |
| 标题字号 | 35px | 27px |
| 内边距 | 20px | 16px |
| 动效时长 | 80–120ms | 60–100ms |

**移动端额外注意**：

1. **触控靶区 ≥ 44×44px**。带投影的按钮视觉尺寸比实际小，要注意 `padding` 补足
2. **长列表（>20 项）里不要用投影**，只保留 2px 描边。投影在滚动时会产生视觉抖动。需要区分时用「墨色 2px 分隔线 + 交替底色」
3. **底部安全区**：固定底栏的投影朝上会侵入内容，改为只用 2px 上边框
4. **不要在小图标上加投影**（<32px 的元素），会糊成一团
5. **横向滚动容器**里的卡片投影会被裁切，改用描边 + 无投影

## 四、可访问性（不能因为风格牺牲）

Neo-brutalism 天然有对比度优势（黑边 + 黑字），但有两个高发问题：

**问题 1：高饱和底 + 白字**
黄 `#FDC800` 上放白字，对比度只有 1.9:1，不达标。**黄色底一律配墨色文字**。
只有紫 `#432DD7`、红 `#DC2626`、绿 `#16A34A` 这类深色填充才配白字。

对照检查：
- `#FDC800` + `#1C293C` → 11.2:1 ✅
- `#432DD7` + `#FFFFFF` → 8.4:1 ✅
- `#DC2626` + `#FFFFFF` → 4.8:1 ✅（勉强，正文建议加粗或换 `#B91C1C`）

**问题 2：硬投影不传递给屏幕阅读器**
`box-shadow` 是纯装饰，不要用它表达状态（如"这个卡片被选中了"）。选中态必须有非视觉的表达：`aria-selected` / `aria-current` / 边框变化 / 前缀标记。

**其他必做**：
- `focus-visible` 永远是可见的粗描边，且 `outline-offset` ≥ 2px（否则描边会被元素自己的墨边吞掉）
- 动效遵循 `prefers-reduced-motion`：关闭位移，只保留颜色变化
- 描边不要用颜色单独承载语义（红色描边 = 错误），必须配文字或图标

## 五、交付自检清单

交付前逐条检查，任何一条不通过就修：

**几何一致性**
- [ ] 所有描边宽度一致（桌面 3px / 移动 2px），没有混用 2px 和 3px
- [ ] 所有投影偏移一致，且**模糊半径全部为 0**
- [ ] 圆角全部在 0–4px 区间，没有胶囊形和 8px+
- [ ] 间距全部落在 `4/8/12/16/24/32` 阶梯上，没有 13px、18px 之类的野值

**风格纯度**
- [ ] 全局搜索 `linear-gradient` / `radial-gradient` / `backdrop-filter` / `blur(`，结果应为 0
- [ ] 没有柔和阴影（`box-shadow` 模糊值非 0）
- [ ] 没有字重 < 400 的文本
- [ ] 过渡时长全部 ≤ 150ms
- [ ] 没有旋转/弹跳类装饰动效

**功能完整**
- [ ] 每个可交互元素定义了 hover / focus-visible / active / disabled 四态
- [ ] 焦点态可见且不被墨边吞掉
- [ ] 所有金额/编号用等宽字体
- [ ] 移动端触控靶区 ≥ 44px
- [ ] 长列表（>20 项）已移除投影

**可访问性**
- [ ] 所有文字对比度 ≥ 4.5:1（大字 ≥ 3:1）
- [ ] 黄色/浅色底上没有白字
- [ ] 状态不单靠颜色或投影表达
- [ ] `prefers-reduced-motion` 已处理

**产品适配**
- [ ] 已确认强度档位（L1/L2/L3）并写进交付说明
- [ ] L1/L2 场景下，改了风格的元素在视觉上自成一系
- [ ] 没有把风格元素撒进不适用的页面（导航、设置、帮助文档）

## 六、案例：示例产品（身份建立 App）

**产品调性**：通过小行动成为想成为的人。温暖、陪伴、正向鼓励。

**判断**：**不适合 L3 全量**。核心矛盾是——产品想说"慢慢来，你可以的"，neo-brutalism 在说"立刻做，你要负责"。全站换皮会让视觉语言与产品人格打架。

**决策**：**L2 局部**，划在"硬承诺"边界上。

| 套用 neo-brutalism | 保持原风格 |
|---|---|
| 挑战卡片（投入了挑战金，是硬承诺） | 底部 TabBar 与导航 |
| 挑战金金额展示 | 首页内容流 |
| 打卡按钮与 21 天方格进度 | 个人中心、设置 |
| 成就徽章与等级 | 用户协议、隐私政策 |
| 挑战失败警示 | 帮助与说明内容 |
| 空状态（还没参加任何挑战时） | 登录注册流程 |

**移动端参数**：描边 2px、投影 `2px 2px 0`、圆角 0–2px、21 天方格用 2px 描边无投影（因为是长列表）。

**注意事项**：挑战失败态的红色要克制。用户挑战失败时本就沮丧，视觉上再"砸"一次会加剧负面情绪——这里的红只用于标题条和数值，正文保持墨色。

**移动端落地清单（app-client）**：
- 在 `App.vue` 或全局样式引入 `assets/neo-brutalism.css`，根节点加 `data-nb-mobile`
- 挑战卡片：`pages/challenge/` 列表项与详情卡改用 `.nb-card`
- 挑战金：`.nb-amount`，金额单位是**分**，展示前 `/100` 并 `toFixed(2)`
- 打卡：`.nb-btn--accent` + `.nb-cells`（21 格）
- 成就徽章：`.nb-badge` 系列
- 空状态：`pages/challenge/` 无数据分支改用大字 + 色块方案
- 保持不动的：`pages/home/`、`pages/profile/`、`pages/stats/` 的既有柔和风格
