# Workbench —— 任务流（要做什么）

uni-workbench 的第二棵树，与 `../knowledge-base/`（存「**是什么**」）并列：这里存「**要做什么**」。

只装**任务卡**。不装知识，不装项目正文。

## 状态轴

```
        新事项
          │
  knowledge-base/00-Inbox/      ← 一切先扔这里（唯一入口）
          │
     ┌────┴─────┐
  是「事」    是「知识 / 资料」
     │             └──→ knowledge-base/10-Knowledge 或 30-Resources
     ▼
  workbench/Next/    排队待做
     │
     ▼
  workbench/Now/     正在做（WIP 上限 1–3）
     │
  ┌──┴───┐
  ▼      ▼
Done   Cancelled
  │
  └──→ 复盘出可复用结论 → knowledge-base/10-Knowledge/
```

## 五态

| 目录 | 含义 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| `Now/` | 正在做 | 已经动手 | 完成 → `Done/`；暂停 → `Next/`；放弃 → `Cancelled/` |
| `Next/` | 排队待做 | 已决定要做，但未开始 | 开始 → `Now/`；降级 → `Later/` |
| `Later/` | 以后再说 | 有价值但未承诺 | 升级 → `Next/`；判定无价值 → 删除 |
| `Done/` | 已完成 | 真的做完 | 复盘提炼后**删除任务卡** |
| `Cancelled/` | 已放弃 | 明确不做了 | 记录原因后**删除任务卡** |

每层规则见各自目录下的 `_说明.md`；卡片格式见 `_模板.md`。

## 铁律

1. **这里是任务，不是项目，也不是知识。** 项目索引在 `../knowledge-base/20-Projects/`，知识在 `../knowledge-base/10-Knowledge/`。同一件事只写一处。
2. **每条任务必须写得出一句「下一步」动作。** 写不出 = 还没想清楚，退回 `Later/` 或 `../knowledge-base/00-Inbox/`。
3. **`Now/` 保持 1–3 件。** 超了就先关掉一件再新增——这是"在做取舍"的证据。
4. **`Done/` 和 `Cancelled/` 是缓冲区，不是仓库。** 每周 / 每季度清理（见各目录说明）。这是「定期捞回、无价值删除」原则的落点。
5. **不复制正文。** 任务卡只写标题 + 动作 + 指向仓库的路径；产出物永远留在产出它的仓库里。

## 命名

`<序号>-<动宾短语>.md`，例如 `01-给 career-hub 补 README 徽章.md`。

序号表达**相对优先级**，不表达截止日期——日期写 frontmatter 的 `due`。
